GitHub Actions workflow cost checker

Paste a file from .github/workflows. You get the settings that usually make a workflow expensive, with the YAML to fix each one, plus a patched copy with the safe fixes already applied.

The file is checked on the server and not stored or logged. Remove anything secret before pasting; workflow files normally reference secrets by name only.

What it checks

  • Duplicate triggers. push on every branch plus pull_request runs the same commit twice.
  • No concurrency group. A new push to a pull request doesn't cancel the run it replaces, so you pay for both.
  • No path filters. A README change runs the whole suite.
  • macOS runners at about 10× the Linux rate, especially on jobs that don't name Xcode, Swift, iOS, or another Apple tool.
  • Larger runners, which are billed even on public repositories.
  • Wide matrices. Every cell is a separate job, rounded up to a whole minute.
  • Frequent schedules. A five-minute cron is about 8,600 runs a month.
  • Missing caches for setup-node, setup-python, setup-java, Playwright, and Cypress.
  • No timeout-minutes. A hung job bills up to GitHub's six-hour limit.

What the patched file changes

Only two edits are applied automatically, because neither can change which tests run:

  • A concurrency group that cancels superseded pull-request runs. Pushes to main still finish. It's skipped for workflows that look like they deploy.
  • timeout-minutes: 30 on jobs that have none. That's a placeholder: set it to roughly three times a normal run.

Everything else is a suggestion. Path filters, matrix changes, and moving off macOS depend on what the workflow is for.
