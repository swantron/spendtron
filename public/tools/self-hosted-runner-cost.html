Self-hosted runner vs GitHub-hosted: break-even calculator

Self-hosted runners have no per-minute charge from GitHub, but the machine and someone's time aren't free. Enter your monthly minutes and what a runner would cost you to run.

What goes in each box

  • Billed minutes: from the detailed usage report, or estimate with the cost calculator.
  • Machines: the monthly price of the VMs or hardware, including disk and network. A cloud VM comparable to the 2-core hosted runner runs from about $15 to $70 a month on demand. Mac hardware costs a lot more.
  • Upkeep: patching images, rotating registration tokens, cleaning disks, and fixing the runner when it wedges. Teams new to it often guess low; two to eight hours a month per pool is common.

Things the number doesn't capture

  • Security. GitHub advises against self-hosted runners on public repositories: a pull request from a fork can run code on your machine.
  • Clean environments. Hosted runners start fresh every job. Self-hosted ones keep state unless you use ephemeral runners or containers.
  • Queueing. A fixed pool makes jobs wait at peak times. Autoscaling fixes that but adds work.
  • Cheaper hosted options first. Before self-hosting, check whether arm64 runners ($0.005), the 1-core ubuntu-slim ($0.002), or fewer macOS runs get you most of the saving.

Want the real numbers instead of estimates?

Load GitHub's detailed usage report on the spendtron homepage for a chart of cost by workflow and runner. It's read in your browser and not uploaded. Or connect the GitHub App to price every job from real runs and get the fixes as a pull request. Both are free.
