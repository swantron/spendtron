Why macOS runners cost about 10× Linux, and when you need one

A standard macOS runner on GitHub Actions is $0.062 a minute. A standard 2-core Linux runner is $0.006. That's a factor of about 10.3. The larger macOS runners are $0.077 (12-core) and $0.102 (M2 Pro, 5-core).

In practice that means one 15-minute macOS job costs about the same as two and a half hours of Linux. A cross-platform test matrix that adds a macOS cell to every pull request often ends up as most of the bill, even though it's one cell out of many.

On public repositories, standard macOS runners are free like the other standard runners. The cost question is about private repositories and larger runners.

When a job really needs macOS

  • Building or testing iOS, iPadOS, macOS, watchOS, or tvOS apps with xcodebuild, or anything that needs Xcode or the iOS Simulator.
  • Code signing and notarizing Mac software.
  • Swift code that imports Apple-only frameworks such as UIKit, AppKit, or SwiftUI.
  • CocoaPods installs and React Native or Flutter iOS builds.
  • Native code where macOS-specific behavior is the thing under test: file-system case-insensitivity, Mach-O linking, Homebrew formulas.

When it usually doesn't

  • Unit tests for a Node, Python, Go, or Rust library that you also test on Linux. A macOS failure that Linux misses is real but rare. Catching it on pushes to main or on a nightly run is usually enough.
  • Linting, formatting, type checking, docs builds. These don't depend on the OS at all.
  • Browser end-to-end tests "for Safari." Playwright runs its WebKit engine on Linux, so a WebKit project doesn't need a Mac runner.
  • Swift packages that don't import Apple frameworks. Swift runs on Linux, and a SwiftPM package can often build and test there.

Keep macOS off every pull request

The common fix keeps full coverage but changes when the expensive cell runs. Pull requests test on Linux. Pushes to main and a weekly schedule test on both:

on:
  pull_request:
  push:
    branches: [main]
  schedule:
    - cron: "0 6 * * 1"

jobs:
  test:
    strategy:
      matrix:
        os: ${{ github.event_name == 'pull_request'
              && fromJSON('["ubuntu-latest"]')
              || fromJSON('["ubuntu-latest", "macos-latest"]') }}
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - run: npm ci && npm test

If the macOS job is the slow, platform-specific one (an iOS build, say), give it a paths filter so it only runs when files it builds actually change.
