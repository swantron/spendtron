What the pull request will and will not change

  • It will apply a timeout, cancel-in-progress on a workflow that is not a deploy, and a short public-repo job moving off a larger Linux runner.
  • It will describe missing path filters, a matrix that multiplies the bill, a duplicate push and pull_request trigger, and a macOS runner with no Apple toolchain. Those edits change which jobs run, so they stay in the pull request body.
  • It will not shorten a healthy run with timeout-minutes. That line is a hang guard, listed last.
